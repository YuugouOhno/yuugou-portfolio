# 本文での魚の描画サイズと移動順

候補1の実測失敗を受け、サイズ補間と移動順は[後続の判断記録](margin-departure-decision.md)で更新した。この文書は候補1時点の判断履歴。

- Context: マネージャー実測のスマホエミュレーション画像で本文の魚が見えなかった。文字用の倍率が本文にも残り、奥行きによって約1px以下へ縮小する。遠方目標への直線的な誘導では、本文の不透明背景の内側に長く留まる。
- Options: 不透明度や明るさのみを上げる／本文の魚サイズを文字から独立させ、側方へ出てから奥へ誘導する。
- Decision: 後者を採用。近い最小サイズの魚を横向きで約3 CSS px、遠い魚を約1.6pxとする。実位置の画面内左右比で奥への誘導を滑らかに接続する。Home専用vertexで色を1.35倍にし、薄いスマホ文字も補助する。
- Why: 本文の保護面・通常操作・既存の配色を維持しつつ、魚の実寸と可視領域への移動を修正できる。速度・加速度上限、Boids、解放ラッチ、実深度による描画変換は維持する。
- Risks: 投影テストだけでは方向・遮蔽・密度を判断できないため、実描画ピクセル検査とPC/スマホ画像の確認が必要。エミュレーションは実機の性能・発熱・Safari差を保証しない。
- Revisit: 独立ブラウザ検証や人間の成果確認で文字の判読・本文の密度・移動の自然さに問題が出た場合。コンセプトへの同意はユーザー提供のPurposeに記載済みで、具体的な倍率・誘導はAIが委任範囲内で選択した。成果物は人間未確認。
